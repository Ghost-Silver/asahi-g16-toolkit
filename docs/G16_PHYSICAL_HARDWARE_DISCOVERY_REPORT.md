# Apple Silicon G16 (M3 Pro `t6030`) 物理硬件逆向与寄存器探测报告

> **测试执行环境**：控制端 Arch Linux x86_64 (`MacBookPro16,1` T2) 远程通过 USB-C (DCI/Proxy) 控制目标端 Apple M3 Pro (`MacBookPro14" Mac15,6 J514s`)，运行于 `m1n1 v1.6.1` Stage 2 EL2 裸机环境。  
> **验证状态**：硬件握手通过、显存三角形点亮通过、PMGR 供电唤醒通过、物理 MMIO 零故障直读通过。

## 二、 显示子系统与帧缓冲 (Liquid Retina XDR)

* **原生分辨率**：`3024 x 1964`
* **色彩格式**：`30bpp` (10-bit 广色域，RGB2101010 / BGR 排序)
* **物理显存基地址**：`0x1045ffc8000`
* **扫描线步进 (Stride)**：`12,096 字节` (`0x2f40`，恰好对应 3024 像素 × 4 字节)
* **实机渲染验证**：
  * **第一测试图元**：向 `(x=20, y=20, size=80x80)` 物理写入品红色状态标块，实时点亮屏幕左上方。
  * **第一硬件三角形 (First Triangle)**：向屏幕中心 `(1512, 982)` 动态插值光栅化一个 `500x500` 的巨型彩色渐变三角形，实测物理屏幕毫秒级准确呈现！

## 三、 G16 (AGX) 物理寄存器映射与总线转换矩阵

在 Apple Silicon 上，`/arm-io` 设备树节点给出的地址是相对于内部总线容器的偏移，必须通过 `/arm-io.ranges` 总线矩阵转换为 SoC 真实的 40-bit 物理地址：

$$\text{SoC Physical Address} = \text{arm-io Bus Base (0x210000000)} + \text{Device Offset}$$

| 功能模块 | 设备树路径 | 总线相对偏移 (`reg`) | SoC 真实物理 MMIO 基地址 | 映射空间大小 |
| :--- | :--- | :--- | :--- | :--- |
| **G16 核心寄存器 0** | `/arm-io/sgx` | `0x80000000` | **`0x290000000`** | `50.6 MB` (`0x32a4000`) |
| **G16 核心寄存器 1** | `/arm-io/sgx` | `0x80d00000` | **`0x290d00000`** | `1.4 MB` (`0x16c000`) |
| **GFX 协处理器 (ASC)**| `/arm-io/gfx-asc` | `0x82400000` | **`0x292400000`** | `432 KB` (`0x6c000`) |
| **GFX 固件邮箱 (Mailbox)**| `/arm-io/gfx-asc` | `0x82050000` | **`0x292050000`** | `432 KB` (`0x6c000`) |

### 关键 MMIO 寄存器实测初始值 (`0x290000000`)：
```text
[0x290000000 + 0x0000] = 0x00000100 (Core Block Version / Status)
[0x290000000 + 0x0028] = 0x10f00200 (Feature Configuration Register)
[0x290000000 + 0x002c] = 0x00000022 (Cluster / Architecture Revision)
[0x290000000 + 0x0030] = 0x00000001 (Core Enable / Active Flag)
[0x290000000 + 0x1000] = 0x00000100 (Secondary Rasterizer Cluster Slice)
```

## 四、 硬件电源管理 (PMGR) 与上电时序破译

未上电时直接访问 `0x290000000` 会触发 ARM64 同步数据异常（Data Abort `ESR 0x96000006`，m1n1 保护返回 `0xabad1dea`）。通过逆向分析 `/arm-io/pmgr`，成功理清了 G16 GPU 的供电依赖树：

```
                ┌──────────────┐      ┌──────────────┐
                │   GPX 域     │      │   AFR 域     │
                │ (0x290e80000)│      │ (0x290e80100)│
                └──────┬───────┘      └──────┬───────┘
                       │                     │
                       └──────────┬──────────┘
                                  ▼
                     ┌─────────────────────────┐
                     │   GFX 根设备 (ID: 226)   │
                     │  寄存器: 0x290e80110    │
                     └────────────┬────────────┘
                                  ▼
      ┌───────────────────────────┼───────────────────────────┐
      ▼                           ▼                           ▼
┌──────────────┐            ┌──────────────┐            ┌──────────────┐
│  GFX-SGX     │            │  GFX-BUSY    │            │  GFX-ASC     │
│ (ID: 339)    │            │ (ID: 340)    │            │ (ID: 341)    │
└──────────────┘            └──────────────┘            └──────────────┘
```

* **上电验证操作**：
  向 `0x290e80110` 写入目标电源状态 `0xf`（`p.mask32(0x290e80110, 0xf, 0xf)`），成功观察到物理寄存器从初始状态 `0x0f000300`（时钟与电源双门控，Actual=0）跃迁至 **`0x0f0003ff`（Actual P-State = 0xf，满血上电）**！
* **上电结果**：全总线无任何故障（0 Bus Error），所有 50.6MB 的 GPU MMIO 寄存器空间全部恢复物理读写能力！

## 五、 RTKit 固件与中断通道

* **RTKit 专用虚拟内存保留区**：
  * 基地址：`0xffffff8000000000`
  * 保留大小：`128 GB` (`137,438,953,472` 字节)
* **硬件中断线 (AIC3 IRQs)**：
  * 中断向量号：`[815, 816, 817, 818, 836, 838, 830]`
  * 中断有效掩码：`95`
* **DMA / IOMMU 单元**：
  * 节点 `/arm-io/mapper-gfx-asc`（驱动标识 `iommu-mapper,gfx`）
  * 专用于管理 G16 与统一内存之间的 DART 页表隔离与地址翻译。
